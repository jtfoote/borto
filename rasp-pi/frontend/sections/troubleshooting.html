B.O.R.T.O. Operator & Field Manual

System Architecture, Setup, & Fault Diagnostics
1. System Overview & Architecture

The B.O.R.T.O. energy storage and UPS system manages power flow between the AC grid, a 12V SLA battery bank, and AC/DC loads to perform automated Time-of-Use (TOU) load shifting and backup power protection.

Power Electronics Stage (STM32)
  • DC1 (Charger/Buck-Boost): Regulates charging voltage and current into the battery bank.
  • Battery Bank: Monitored for terminal voltage and current draw/charge.
  • DC2 (Boost Stage): Steps up battery voltage for the high-voltage DC bus (measured at TP5).
  • Inverter Stage: Converts the DC bus to AC output at the receptacle terminals.
  • Enclosure: Monitored via RTD temperature sensor for thermal safety limits.
Telemetry & Control (Raspberry Pi)
  • UART Serial Link: Streams 10-variable telemetry packets between the STM32 MCU and the SQLite database.
  • Local HMI: On-board I2C LCD and two adjacent tactile navigation buttons.
  • Web Dashboard: Containerized FastAPI + Alpine.js interface for live plotting, TOU scheduling, and sensor calibration.
2. First-Time Network Setup & Local LCD Navigation

Captive Portal Wi-Fi Provisioning

If BORTO cannot reach a saved Wi-Fi network on boot, it automatically broadcasts a local setup hotspot:

  1. Power on B.O.R.T.O. and wait for the on-board LCD to display Connect to BORTO_Setup.
  2. Connect a Wi-Fi-enabled device to the BORTO_Setup network using default password bortoinit.
  3. Open a web browser and navigate to http://10.42.0.1.
  4. Enter your local network's SSID and WPA2 Password and click Connect.
  5. Within 20 seconds, BORTO_Setup will disconnect and the LCD will update to display a local IP address (e.g., 192.xxx.x.x or 10.xxx.x.x).

On-Board LCD & Tactile Buttons

During normal operation, the LCD displays B.O.R.T.O. Ready. Press the two tactile buttons adjacent to the LCD to cycle through menus, including the Local IP screen, real-time bus voltages, and active fault states.

3. STM32 Fault & Error Code Reference

When System Status enters 2 - ERROR, the STM32 reports a specific fault code in the telemetry packet:

Code Fault Name Description / Cause Corrective Action
0 NO_ERROR System operating within nominal parameters. None required.
1 OVER_VOLTAGE DC1, Battery, or DC2 bus exceeded safe voltage limit. Disconnect load/source. Verify DC1/DC2 setpoints and voltage sensor slope/offset in Settings → Debug Options.
2 UNDER_VOLTAGE Battery or bus dropped below low-voltage cutout (LVC). Switch system to Force Charge or reduce load. Check battery terminal voltage with a DMM.
3 OVER_CURRENT Current draw exceeded hardware safety threshold. Disconnect AC/DC load and inspect for short circuits. Verify current sensor calibration.
4 UNDER_CURRENT Unexpected open-circuit or reverse current condition. Check fuse integrity, breaker connections, and battery terminal leads.
5 OVER_TEMPERATURE Enclosure/MOSFET temperature exceeded thermal limit. Power down load, verify enclosure airflow/heatsinks, and allow hardware to cool before resetting.
6 UNDER_TEMPERATURE RTD sensor reading below minimum operating threshold (often an open sensor wire). Inspect RTD temperature sensor wiring and check temperature offset in Debug Options.
7 PWM_FAULT Hardware gate driver fault or duty cycle saturation on DC1/DC2. Inspect half-bridge MOSFET drivers and verify duty cycle readouts in Debug Options.
4. Hardware Verification & Sensor Calibration Guide

If telemetry plots on the Metrics tab diverge from physical Digital Multimeter (DMM) readings by more than ±0.5V:

  1. Connect a DMM across the target test points (e.g., positive lead on TP5 and negative lead on TPGND for DC2 Boost output).
  2. Navigate to Settings → Debug Options and toggle Enable Hardware Debug & Calibration Mode.
  3. Click ↻ Read from MCU to fetch the active linear calibration parameters ($y = mx + b$).
  4. Adjust the Calibration Slope ($m$) and Calibration Offset ($b$) for the corresponding sensor (DC1 Voltage, Battery Current, DC2 Voltage, or Temperature).
  5. Click Write Sensor Calibration to transmit the updated coefficients to the STM32 over UART.
5. Common Symptoms & Quick Fixes
Symptom: Charts are frozen or showing "--" values

Cause: The UART serial service container is not receiving packets from the STM32, or the STM32 is unpowered.
Fix: Verify the STM32 board has power and check the /dev/serial0 RX/TX jumper connections. If hardware connections are secure, reboot BORTO via Settings → System & Power Control.

Symptom: TOU Schedule is triggering at the wrong time of day

Cause: If BORTO booted without internet access (offline or AP mode), the Raspberry Pi clock may have drifted due to lack of NTP sync.
Fix: Go to Settings → Time of Use (TOU) Schedule and click Sync Pi Time with Browser to push your device's local clock to the system.

Symptom: Dashboard is stuck on the red ERROR banner during testing

Cause: Either the STM32 is reporting Status 2, or Manual Status Code Override is enabled.
Fix: Check Settings → Device & Operating Mode and ensure the Manual Status Code Override switch is turned off.
